AUTOSTOP CRM
Compact server handoff

Work from /opt/autostopcrm. The canonical source for operations, rollback, and
maintenance is docs/OPERATIONS_RUNBOOK.md; use current state and that runbook
for diagnosis. This note keeps release boundaries, not a rigid procedure.

Runtime: branch autostopcrm-v1; CRM https://crm.autostopcrm.ru; MCP
https://crm.autostopcrm.ru/mcp. Compose services: autostopcrm, searxng,
crawl4ai. Data: /opt/autostopcrm/data -> /home/autostop/.minimal-kanban.

Deploy only with explicit owner intent, a clean checkout, and exact
origin/autostopcrm-v1 parity. CRM_DEPLOY_BRANCH=autostopcrm-v1 is fixed in
deploy.sh; do not pass a branch or Git-sync override:
./deploy.sh

Hard boundaries:
- Preserve .env, data, backups, active volumes, and dirty parallel checkouts;
  never expose tokens or full environment dumps.
- Never edit state.json, audit-archive, operator-activity, repair-order, or
  cashbox ledgers manually. Repair-order numbers are immutable.
- An approved maintenance write needs dry-run and a verified backup. Anonymous
  public API/MCP reads and every write remain blocked.
- Keep production OAuth enabled, AUTOSTOP_MCP_EMBEDDED_OAUTH_ENABLED=0, and its
  encrypted state key stable. Public clients retain exactly 24 Gateway v2
  tools; agent writes use context -> action contract -> named dry_run/apply ->
  reread.
