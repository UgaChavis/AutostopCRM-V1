# Separate all-profile cold recovery contract v1

This is the executable preparation and quarantine layer for a **new** cold
authority. It does not reinterpret the original warm policy, its historical
process scope, or an exited SSH transport as a current native permit. The two
permanently denied roles remain denied. No production operation is performed
by importing these modules or running the private fixture tests.

The bounded controller uses a distinct preparation request and final sealed
cold plan. Request S/A/C/E retains one deployment-lock owner through preparation,
backup, independent restore, final admission, six new execution slots and a
separate one-shot CRM replacement. Neither a source installation nor a request
entry grants application admission. Production execution remains unauthorized
until the exact release tuple, producer evidence, qualified GitHub jobs and
future-window native and business acceptance have all passed.

The original eight units and scheduler hold remain closed. The six execution
slots have new attempt-derived unit identities; the seventh writer is the CRM
embedded Manager library. No original unit/drop-in or historical pending bytes
are rewritten or adopted. A terminal safety close permanently refuses reopening
the same epoch. An unknown submitted outcome never permits another submission.

## Public interfaces and versioned documents

* `j1_forward_cold_authority.profile_input_template()` returns the exact fields
  required for all six profiles. Its `None` values are invalid placeholders.
* `compile_policy(...)` / `compile_policies(...)` require an exact source package,
  source index, interpreter, runtime and startup inventories, environment,
  effective unit, guard/native references, fixed argv/cwd and credentials.
  There is no preserved-five exemption and no `native_permit=true` input.
* `compile_package(...)` validates the entire immutable reference graph before
  returning canonical bytes for exclusive publication. It produces no grant.
* `validate_package(ref, read_reference=..., required_scope=...)` checks artifacts
  and rereads their entire reference graph. It does not infer native truth.
* `j1_forward_cold_native.verify_package(...)` repeats the fresh native checks.
  The default provider has fixed production paths and commands. It never calls
  an existing ready/RPC/guard command, queries business data, signals a production
  process, starts/stops a unit, installs a policy, or changes a barrier.
* `CheckedDispatcher.inspect(unit)` and `j1_forward_cold_guard.inspect(...)`
  enforce the exact unit, package, generation, interval and source bindings.
  `current_process=True` additionally compares the actual interpreter, argv,
  environment, credentials and cwd before a private probe effect.
* `j1_forward_cold_install.inert_stage(...)` copies exact protected source and
  configuration into fresh namespaces under the original lock. Seven binding
  manifests and empty state/run roots are required; no service starts here.
* `j1_forward_cold_release.py issue-request` replays the exact-source GitHub
  qualification before publishing a request ticket. `launch` reserves one
  transient controller submission; `controller` is its fixed native consumer.
  `settle` only closes the new dispatch epoch and records a terminal refusal.
  `inspect` and the Windows custodian use the separate typed cold contract.

The qualification binds the full CRM source inventory and exact Git revision
and tree to quality, full Linux, full Windows and native systemd jobs. It is
distinct from the package's smaller observer-consumer digest. The worker reads
the immutable qualification; the issuer independently rechecks GitHub before
issuing. A five-job legacy quality receipt alone is insufficient.

Package schema: `autostop.j1.crm-manager-cold-authority-package.v1`.
Its contract is `all_six_profiles_cold_quarantined_v1`. A future controller must
use the distinct plan schema `autostop.j1.crm-manager-cold-forward-plan.v1`,
scope `crm_and_manager_all_profiles_cold`, and `cold_authority_package_ref`.
The warm plan and warm baseline validators must continue to reject it.

The exact package fields are `schema`, `scope`, `contract`, `binding`,
`predecessor_ref`, `source_package_ref`, `policies`, `permanent_denied_units`,
`closure_ref`, `hold_ref`, `retirement_ref`, `quarantine_ref`, `pending_ref`,
`kernel_ref`, `lifecycle_ref`, `original_hold_ref`, and `hold_checkpoint_ref`.
Every reference has exactly `path` and
`sha256`; every typed document rejects extra fields. The package's lifecycle

The binding contains a new attempt UUID and generation UUID, current boot UUID,
exact consumer digest, CRM and Manager candidate revisions, deployment-lock

documents share that exact binding. Source package provenance is a mandatory
independently accepted input of the future release window; its digest does not

## Actual native evidence, not flags

Production packages are immutable at
`/etc/autostop-crm-forward/cold/v1/packages/<attempt-UUID>/authority.json`.
The guarded slot derives its exact package reference from the fixed epoch;
there is no replaceable global authority selector. Configuration is fixed under
`/etc/autostop-crm-forward/cold/v1`;
consumer files are under `/usr/local/libexec/autostop-crm-forward-cold/v1` and
state under `/var/lib/autostop-crm-forward/cold/v1`. There is no environment
override. Missing fresh inputs refuse normally rather than inheriting warm
permission. The implementation is not a permanent `unimplemented` refusal.

Production pending-disposition documents use the explicit v2 schema. Original
Manager operation IDs are retained as bounded strings in both disposition and
tombstones; only filesystem keys are SHA-256 encoded. Unknown outcomes require
review and remain forbidden for replay. Existing private v1 fixture documents
cannot satisfy the production scope.

Capture snapshots authenticate each reference once, reuse only identical
captured bytes during pure semantic validation, and re-read every physical
source with the same inode/version before accepting the capture. This retains
no descriptor per graph entry. Off-host restoration uses captured bytes only;
it never stats a logical production path or grants native authority. The native
closure checks before and after capture remain mandatory.

`Controller.ready()` owns one bounded `PackageObservation`. It decodes the
immutable package/capsule once and admits at most nine nested observations in
the same process and thread. Every observation freshly measures closure,
retirement, ingress, the original scheduler hold, pending quarantine and the
kernel, including its actual account/thread RPC and mapped-file checks. The
epoch and each role's acceptance and Telegram frontier remain fresh too.
Complete source/runtime file versions are checked around these measurements;
new runtime state directories are outside the immutable source/runtime roots.
Before returning, all captured source/opaque/capsule bytes and every installed
source/runtime byte are independently reread, followed by fresh native and
epoch checks. Identical capsule bytes need no second decompression. An observed
change or expired binding refuses, including same-byte inode replacement and a
byte mutation reverted before the next cut. The context is poisoned on failure
or exit and cannot be reused by another operation, provider, process or thread.
Standalone verification and child E admission retain their full qualification;
this optimization neither extends a deadline nor grants execution authority.

New execution-slot units use a single fixed `ExecStart` for `guard launch` and
strictly reject any `ExecCondition` or extra hook. The diagnostic `guard check`
still performs its full independent qualification. A is the independently
observed bootstrap process; it does not assert application entry. The worker
reads its ticket and A, then performs one full package/native qualification in
`_active_parent`, immediately before the ordered parent O / child O boundary.
The parent reference graph, final plan, child context and ticket are pinned too.
Under O, the callback reads actual parent identity and ownership, epoch, safety
and complete immutable file versions. It repeats that checkpoint after durable
C and before E. A failed checkpoint leaves C durable, E false, and never reaches
application credentials, cwd or exec. All large file hashing stays outside O.
An unknown S still cannot submit again. The original eight units are unchanged.

The required hosted Linux systemd job also runs `scripts/rehearse_cold_systemd.py`
with the fixed `/usr/bin/python3` bootstrap. It delegates the actual new unit
template, systemd start and native unit/cgroup/process observers. The standalone
guard consumes a real private parent S/A/C/E journal and continuously held D.
The synthetic child context declares cwd `/` before its initial ticket; no
accepted ticket is rewritten. After observing the actual wrapper, the test OS
adapter can corrupt its private application source, retire its owned artificial
kernel, or revoke its parent before publishing A. Each must leave child C/E
false despite the empty ExecCondition. The positive case records one S/A/C/E,
one entry sentinel and one systemd submission, including a duplicate caller.
This proves the template and guard OS path only. Source eligibility, restore
proofs, authenticated kernel operation and application/business acceptance
remain outside this artificial package's claims.

Loaded-unit reads keep their five-second total budget. Since systemctl can omit
empty arrays even with `--all`, only a typed Service `GetAll` response with the
exact property signature and an empty array can fill a known omitted hook or
`EnvironmentFiles`. A typed Unit response must match the requested identity and
state. An empty displayed Job becomes `0` only with `(uo) = [0, "/"]`. Two typed
queries and an unchanged final systemctl read share that budget; missing or
unknown properties, wrong types, active jobs and changed snapshots refuse.
The response encoding follows the pinned
[systemd v255 D-Bus interface](https://www.freedesktop.org/software/systemd/man/255/org.freedesktop.systemd1.html)
and [busctl JSON encoder](https://github.com/systemd/systemd/blob/v255/src/busctl/busctl.c).

Before OPEN, runtime checks use only health, UI hashes, authenticated metadata
and the MCP tool catalog. After OPEN, the bounded `get_runtime_status` relay
checks CRM-to-Store compatibility. Both explicitly report business acceptance
as false. Customer-facing business acceptance remains a separate release-window
gate, alongside the Store candidate's quiet backup, independent restore and
schema/principal readback. The cold controller does not deploy Store.

The provider rechecks physical protected source/runtime/startup files, the
complete source tree, exact effective unit records and non-ignored dispatch
conditions, all eight owned deny files, inactive old units, the original
deployment-lock inode and the *actual controller descriptors' flock records*.
An unrelated process holding a replacement lock cannot repair a lost interval.

`j1_forward_cold_history.py` validates the predecessor anchor against the exact
retained original plan, baseline, closure and process-scope references. It
derives the entire freeze/transport/native-control actor union, Unix endpoints
and stdio pipe inventory. Omitting one actor or substituting an unrelated empty
cgroup refuses. A collected cgroup path is accepted as absent only after exact
semantic coverage has been established. A different boot requires a freshly
accepted scope; old PID numbers cannot act as cross-boot identities.

Retirement binds that complete actor scope. It distinguishes
PID birth from PID number and inspects pidfd liveness without signalling a
production PID. A new cold containment receipt is required; no current arbitrary
PID is adopted to make the scope pass. The production provider requires empty
retired cgroup populations, absent old Unix endpoint identities and absent old
pipe capabilities. Hashes, empty job lists, `idle`, or SO_PEERCRED alone cannot
establish complete ingress ownership or continuous revocation. Completeness of
the accepted actor/ingress producer remains an explicit input, not a conclusion
drawn from an empty snapshot.

The new kernel must have a fresh boot/generation/PID-birth identity, an accepted
kernel policy binding source/interpreter/runtime/startup/environment/unit,
actual argv/cwd/credentials and process binding, a stable readiness document,
and independently observed
read-only cache mounts in PID1 and the daemon namespace. The old kernel policy
may be preserved as provenance; it cannot supply the new cold permission.

Pending requests have stable operation UUID and payload digest. Each disposition
is one of `applied_readback`, `not_applied_terminal`, or `unknown`; **all have
`retry=forbidden` in this layer**. Missing receipts/effects are never translated
to `not_applied_terminal`. Production positive outcomes require a separately
accepted producer and independent readback checkpoint; this observer cannot
manufacture external-effect truth from local evidence hashes. An unknown
business outcome still needs reconciliation before a release controller may
decide whether to reopen its ingress. There is no replay API here.

`j1_forward_cold_hold.py` independently measures the original Scheduler global
hold. It requires exact database device/inode/owner, bytes matching a quiet
backup, absent WAL/SHM/journal, original attempt hash and reason, hold owner hash
and revision. It queries every runtime lease including archived jobs and every
sending outbox row. Invalid timestamps or active work refuse. It uses raw
`mode=ro&immutable=1`, not Manager's writable `status/initialize/connect` path,
and checks bytes/identity again afterwards. A saved enabled receipt or the new
ingress marker cannot replace this SQL measurement. Complete writer closure and
continuous dispatch hold remain prerequisites. The original hold receipt and
new database checkpoint have separate package references.

## Private executable fixture

Run the bounded focused suite, without a project/runtime/production launch:

```sh
python -m unittest tests.test_j1_forward_cold -v
```

`Fixture()` creates a new private `autostop-cold-native-*` directory and starts
only six fixed old worker children. Their AF_UNIX listeners use actual peer
credentials; same-UID foreign PIDs are rejected. Requests have an independently
persisted client catalog and durable intent/terminal/effect files. Before an
effect a worker takes the real dispatch flock and checks the hold and its deny
file. The producer writes all eight deny files and the hold, takes the dispatch
flock, then retires only its captured children with `pidfd_send_signal`. It waits
on pidfds and reaps the exact owned processes. No numeric `kill(pid)` fallback
exists. It never accepts an external PID, command, environment or service name.

It snapshots request dispositions after retirement, records unparsed/backlog
ingress as retired without replay, and starts a separate fresh private kernel
process. It compiles all six new policies from the copied actual reviewed
consumer/source bytes, publishes the typed package exclusively with fsync, then
runs the same validator and native verification sequence. Six real probe
processes enter the shared guard with their actual profile, argv, environment,
credentials and cwd and publish exclusive synthetic receipts. A duplicate probe
cannot replace an earlier receipt. The eight fences and hold remain present.

Fixture scope is exactly `native_fixture`; production scope is
`production_native`. The default production caller rejects a fixture before
native observation. Renaming a scope string cannot substitute for the fixed
production provider's independent measurements. The private cache is a mode
0400 fixture file, explicitly **not** a claim of a real read-only mount or
production kernel readiness. Source revision fields in this fixture are
synthetic; actual source byte hashes are still checked.

The fixture inventory covers its registered client catalog and published
intents. An unregistered published intent refuses packaging. Unparsed kernel
backlog cannot be enumerated as request IDs and is never called an empty app
queue. The source's closed child topology is a fixture assumption; production
requires its own complete accepted containment/ingress producer.

The fixture creates only a small synthetic Scheduler registry and quiet backup.
Clearing its database hold is detected even while the old receipt says enabled
and the new ingress marker remains. Read-only measurement creates no SQLite
sidecars. Fixture FD checks inspect only its own controller and owned children;
they do not scan production process FDs.

Closing the fixture only stops/reaps its own children, closes its own sockets
and descriptors, and removes its own private directory. Uncertain cleanup
retains evidence and fails. Expiry, lost locks, stale bindings, corrupted files,
extra source files and missing facts refuse without opening any fence.

Linux uses actual pidfd, flock, AF_UNIX and SO_PEERCRED. Those native cases have
the documented Windows exclusion `Requires real Linux flock, AF_UNIX and
SO_PEERCRED`; portable compiler/record tests remain mandatory on both platforms.

## Integration and release acceptance

The controller explicitly uses the cold plan and durable recovery-store chain,
typed data/control backup, independent off-host signature and final COMMIT.
All six new role entries and the separate CRM entry are one-shot permissions
bound to the final plan. Only the new shared dispatch epoch opens after all
seven native acceptances and durable HEAD. The original eight barriers and
original scheduler hold remain installed; no old duty helper is started.

The effectful native producer, actual new kernel bootstrap and complete old
ingress/pending inventory must be independently exercised with this controller.
The real Codex executable exceeds the legacy control-archive leaf budget; its
separately versioned runtime codec and measured resource acceptance are required
before a production package can qualify. Private Python workers do not prove
this runtime boundary. No current production grant is created by this source.

Cold control archives use explicit codec v4; existing v3 archives remain
readable with their original limits. Ordinary source and JSON leaves retain
their bounds. Only independently derived typed runtime leaves can use the
384 MiB opaque-file allowance within the 512 MiB total payload budget. The
manifest declares every large leaf's exact path, size and SHA256; independent
semantic restore must derive that same inventory. A declaration alone grants
no native runtime or startup authority. Warm transport budgets are unchanged.

Closure preparation, a fixture probe, a package hash or a passing source test
is not production acceptance or proof that an external request may be replayed.

The cold-v4 runtime capsule is a data format, not another launch authority.
`j1_forward_cold_runtime_capsule` builds a deterministic gzip/tar of the complete
Python base and one shared six-role venv. Runtime-index v2 retains every regular
file, directory and internal relative symlink with its exact mode, size and
SHA-256. Its entries use relative names rather than controller reference
objects, so the control graph stores the compressed artifact once. Codex stays
a separately typed native executable; it is not copied into the capsule.

The current bounds are 32,768 indexed entries, 1.5 GiB expanded and 192 MiB
compressed, within the cold-v4 512 MiB total control budget. These are hard
acceptance bounds, not claims that a measured release fits them. Independent
restore streams every member, rejects extra entries, links outside either
runtime root, unsafe tar metadata and expansion beyond the index, and hashes
every output without importing or executing archived Python. Live admission
separately hashes the complete installed tree and rejects additional files.

Production roots are fixed to the selected Manager revision's `python` and
`venv` directories. Physical Python executables and `pyvenv.cfg` must refer to
these exact final prefixes. Installation uses private inert staging and never
rewrites prefixes or replaces an existing conflicting runtime. A crash after
one root rename permits only reconciliation against the identical full index.
Publication, materialization and restore receipts grant no activation or
business permission. Actual artifact size, process-tree RSS, off-host restore
and six-role startup remain measured release qualifications.

Production pending-disposition v2 and tombstones v2 retain each original raw
operation ID and an explicit fingerprint kind. A hash of an observed old row
is `observed_record_sha256`, never an original payload hash. It permits only
the `unknown` disposition and forbids retry. The fixed catalog reader must
independently remeasure the accepted source-defined durable tables/files and
the separate stopped original CRM incarnation. Retired, unenumerated RAM is
reported explicitly; it is not called an empty request population. Historical
fixture v1 keeps its original payload-hash shape and meaning.

Kernel v2 binds the Python supervisor and actual Codex child separately. Before
OPEN, fresh preparation verifies the owned initial thread and account/source/
process/socket bindings. After OPEN the read-only native observer may use
runtime-identity checks only while the actual durable private HEAD, COMMIT,
sealed plan, epoch and public admission cut agree under the new dispatch SH
lock. That lock remains held throughout the observation and final reread.
An existing controller EX may be borrowed only as its actual linked descriptor
with matching device, inode, ctime and current-owner lock proof. The original
quarantine EX is a different lock and cannot substitute for this descriptor.

The fixed kernel cache view is a read-only bind of this attempt's separately
indexed `kernel/cache-source`. Native verification hashes the complete source
and view, checks the bind identities and the intended mount/options in PID 1,
supervisor and Codex namespaces. The cache checkpoint is also part of the real
typed data backup; off-host acceptance must compare its index with the restored
data. A read-only mount record alone grants neither dispatch nor acceptance.


## HTTP ingress between CRM generations

Stopping the old container does not drain requests buffered by a shared proxy.
The cold candidate therefore uses an immutable `autostop.j1.cold-http-ingress.v1`
configuration in its accepted `crm-embedded` directory. Board and MCP addresses
have separate prefixes bound to attempt, boot, generation and both source SHAs.
`expected_prefixes` derives each address with a separate transport domain; an old
address cannot be reused with a different binding. Addresses are routing cuts,
not credentials. Existing bearer, operator and OAuth checks remain mandatory.

The fresh generation remains private before retirement. The producer must check
custody of all generation-bearing inputs and publish the new address only after
retirement. Prior nonpublication remains an explicit operator/source premise;
syntax validation alone proves neither chronological freshness nor queue drain.
A leaked or previously published future generation requires STOP and a new
preparation. The attempt ID in a unit name is not a secret.

The Board guard rejects old, missing and aliased prefixes before reading a body
or calling authentication, services or the database, including Expect/continue.
The MCP guard sits outside SDK authentication. Only exact read-only discovery
metadata may remain at root; token, registration, consent and MCP requests must
use the current prefix. There is no old-address redirect or proxy auto-prefix.
New pages freeze their own prefix, including assets and lazy modules. Explicit
stale URLs are preserved and denied. New OAuth forms retain their issuing prefix.

Container spec v2 and CRM acceptance v2 bind the immutable HTTP config reference,
actual process environment, read-only role mount, candidate image and seventh
Manager binding. The cold CRM creates its own listener and refuses an occupied
port instead of adopting another API. Health and readiness use that same prefix.

Before opening dispatch, and again inside production marker-removal authorization,
ColdHost independently checks both local and public transport status against the
actual config hash, epoch and CRM source. Old and stale paths must return the
application generation denial; maintenance must still be active. The same exact
accepted container/process is checked before and after this bounded read-only
probe. Probe receipts enter the terminal proof graph. Terminal readiness after
marker removal does not require maintenance to remain active.

The future window must explicitly configure browser/connector URLs for the new
Board base and MCP issuer/resource. A new address does not authorize replay of
an old request. These checks are implemented for the future isolated release;
no production address, proxy, marker or container was changed during preparation.

## Closed capture interval

`cold-capture-entry.json` and `cold-capture-completed.json` bind the same plan,
package, epoch and complete source-version cut. Every artifact boundary gets a
separate `autostop.j1.cold-capture-boundary.v1` receipt. It freshly checks all

The cold custodian refuses a production response without the attempt-bound
completed interval. It resolves every interval document from the independently
restored control payloads, verifies their sizes and hashes, and validates both

the corresponding live controller paths cannot satisfy this restore check.
